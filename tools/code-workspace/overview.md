# 交付说明 — 本地代码工作区（code-workspace）

浏览器里的文件管理器 + 代码编辑器：选一个本地文件夹并**授权读写**，即可浏览目录树、
新建 / 重命名 / 移动 / 删除文件，并在离线编辑器里改代码、`Ctrl+S` 直接写回磁盘。
零后端、零 CDN、数据不离开浏览器。

---

## 版本基线

* 当前 **v1.0.2**（`manifest.json` → `latest: "v1"`），起步即用版本化 SPA 架构，后续新版本追加 `V2/`、`V3/` 即可。
* 与 `tools/codebase-context` 的关系：**完全独立的子项目**，只**复制**了它的设计令牌与若干通用模块，
  没有一行共享代码、不互相引用。codebase-context 保持只读不变。
* 版本沿革：`1.0.0` 首版 → `1.0.1` 修「每个文件都只读」故障 + 错误呈现改造 →
  `1.0.2` 只读提示残留修复 / 信息栏偏好持久化 / favicon 与 logo 同构 / Web 字体 /
  编辑器底色重调 / Markdown 编辑·预览双模式。

## 能力清单

### 一、文件管理

| 操作 | 实现方式 | 说明 |
|---|---|---|
| 浏览 | 递归扫描根目录建树 | 默认隐藏 `.git` / `node_modules` 等噪音目录，顶栏可一键显示全部；条目上限 2 万条 |
| 新建文件 / 文件夹 | `getFileHandle(name,{create:true})` / `getDirectoryHandle` | 名称经 `safeName()` 校验，并查重防止覆盖 |
| 重命名 | 复制 + 移除原路径 | 见下方「为什么移动也是复制」 |
| 移动 | 复制 + 移除原路径 | 目标目录用下拉选择，排除自身与子目录 |
| 删除（伪删除） | 复制到 `.cw-trash/` 再移除原路径 | 二次确认需**输入文件名**才能提交 |
| 回收站 | `.cw-trash/manifest.json` 记录「副本名 → 原路径」 | 可还原到原位置；原位置已被占用时自动改名避让 |
| 彻底删除 | 移除回收站内的副本 | 同样需输入文件名确认，明示不可恢复 |
| 另存/写回 | `createWritable()` + `write()` + `close()` | `Ctrl+S` 或「保存」按钮 |

### 二、代码浏览与编辑

* 离线编辑器 **CodeMirror 6**，覆盖约 100 种扩展名映射（含 lezer 原生解析器 + legacy stream 模式）。
* 多标签：切标签保留各自的**撤销历史 / 光标 / 滚动位置**（单 EditorView + 多 EditorState）。
* 未保存状态：标签页黄点 + 顶栏「未保存」标记；关闭有改动的标签会拦一次；离开页面前 `beforeunload` 提示。
* 快捷键：`Ctrl+S` 保存、`Ctrl+W` 关闭标签、`Ctrl+B` 折叠信息栏；编辑器内继承 CodeMirror 默认键位（`Ctrl+F` 搜索等）。
* 只读保护（刻意不做编辑的情形）：
  * 二进制文件（按扩展名表 + 读前 8KB 扫 `0x00` 双重判定）；
  * 非 UTF-8 文本（如 GBK / UTF-16）——直接解码失败就拒绝编辑，避免「读进来乱码、存回去写坏原文件」；
  * 超过 3 MB 的文件。
* 只读提示是**绑定在标签上的临时状态**：切到普通文本标签（或回到欢迎页）时自动收起，不残留。

### 三、Markdown 编辑 / 预览双模式

打开 `.md` / `.markdown` 文件时，编辑器工具栏出现**「编辑 · 预览」分段切换**：

| 行为 | 说明 |
|---|---|
| 进入时取哪一档 | 取用户上次选的那一档（存 `cw-md-preview`），首次默认「编辑」 |
| 预览内容 | 从**编辑器当前内容**实时渲染，未保存的改动立刻可见——不需要先存盘 |
| 保存 | 两种模式下 `Ctrl+S` 都能存，预览态不会吞掉快捷键 |
| 非 MD 文件 | 分段切换自动隐藏，编辑器仍占满工作区 |
| 只读文件 | 预览可用（纯查看），编辑态保持只读提示 |

MD 渲染器（`V1/src/mdview.js`）是**零依赖**的，支持标题 / 围栏代码 / 引用 / 嵌套与有序列表 /
任务列表 / GFM 表格 / 分隔线 / 粗斜体与删除线 / 行内码 / 链接 / 图片 / 自动链接。

**安全做法（有意取舍）**：先把整段原文 `escapeHTML` 全量转义，再在转义后的文本上套白名单内联规则。
这样输出里出现的每一个 `<` 都是渲染器主动生成的，天然免疫 XSS；代价是**不支持内联 HTML**
（写 `<div>` 会原样显示为文字）。链接与图片来源另走协议白名单，`javascript:` / `data:` / `vbscript:`
会被降级成普通文本。

### 四、界面偏好会记住

主题（`cw-theme`）、信息栏显隐（`cw-info-visible`）、MD 模式（`cw-md-preview`）三项都持久化到
`localStorage`，刷新后保持。统一走 `V1/src/prefs.js`：命名空间 `cw-`，JSON 读写全包 `try/catch`
——隐私模式下 `localStorage` 直接抛异常时**静默降级为默认值**，不影响主流程。

## 三个关键设计决策

### 1. 为什么「移动」也是复制？

**File System Access API 没有 rename / move 原语**，只有 `getDirectoryHandle` / `getFileHandle` /
`removeEntry` / `createWritable`。所以重命名、移动、伪删除在底层都是同一条路径：

```
在目标位置写出副本 → removeEntry 原路径
```

复制走 Blob 直写（`writable.write(file)`），不解码文本，二进制文件同样安全；目录则递归复制。
复制成功但原路径移除失败时会**回滚目标副本**，不留重复文件。

### 2. 伪删除与真删除的兼容设计

删除只有一种底层手段：`removeEntry(recursive)`。所以「伪删除 vs 真删除」的差别**不在用哪个 API**，
而在于**是否先把副本写进回收站**。这个差异被收敛到唯一出口 `deleteEntry()`：

```js
// V1/src/fsrepo.js
export const DELETE_MODE = "trash";        // 'trash' | 'permanent'

export const CAPABILITIES = {
  softDelete: true,    // 回收站可用
  hardDelete: false,   // 真删除：能力已实现，UI 未接入
  restore: true
};

export async function deleteEntry(path, opt = {}) {
  const mode = opt.mode || DELETE_MODE;
  if (mode === "permanent") { await removeEntry(path); return { mode }; }   // ← 真删除分支已就绪
  /* trash 分支：先落地副本到 .cw-trash/，再 removeEntry 原路径 */
}
```

**将来要上真删除**：把 `DELETE_MODE` 改成 `"permanent"`（并把 `CAPABILITIES.hardDelete` 置 `true`），
UI 会自动跟随——信息栏按钮文案、二次确认弹窗的「当前删除方式」提示都由这两个常量驱动，其余代码零改动。

### 3. 权限模型

* 目录选择一律 `showDirectoryPicker({ id: "cw-root", mode: "readwrite" })`，选择器上直接带读写语义。
* 选完再查一次 `queryPermission({mode:"readwrite"})`，不足则 `requestPermission()`（需在用户手势上下文中）。
* 顶栏常驻「读写 / 只读」徽标；保存前若权限掉了会再申请一次，失败则明确报错而不是静默失败。
* **拖拽文件夹不提供写入权限**（`webkitGetAsEntry` 拿不到可写句柄），因此拖拽被明确拒绝并引导走「选择文件夹」，
  不做「看似能用、一保存就失败」的半残模式。

## 外观：排版与配色

### 字体（本工具唯一的外部依赖）

排版观感对齐 `codebase-context`：**Space Grotesk**（界面）+ **JetBrains Mono**（代码 / 数值），
由壳的 `<link>` 从 Google Fonts 引入，带 `display=swap`。

这是本工具**唯一的外部资源**，其余部分仍是零 CDN、零 npm。断网或被墙时：

* `display=swap` 保证先用兜底字体渲染，不会白屏等字体；
* `V1/style.css` 的 `--font-sans` / `--font-mono` 都以完整系统字体栈收尾
  （`-apple-system` / `Segoe UI` / `PingFang SC` / `Microsoft YaHei` …）；
* 降级结果**只在字形观感上有差异，功能零影响**。

单文件快照（`dist/`）同样保留这两条字体外链——打包器把它归类为「离线仅视觉降级」，不算阻塞型外链。

### 编辑器底色

亮色模式的编辑器底色取自 `codebase-context` 的 MD 预览底色 `rgb(240,245,250)`，
换算为设计令牌体系里的 `oklch(96.8% 0.0086 248)`（换算用脚本精确反算，不靠肉眼估）。
行号槽与当前行高亮同步下调，避免出现「底色变了、行号槽还刺白」的断层。

暗色模式**没有照搬**：原值 `oklch(17.5%)` 实为 `rgb(13,17,22)`，已接近纯黑，
长时间盯代码时对比过强、也丢掉了色相倾向。改为 `oklch(24.4% 0.0145 248)`（≈ `#1b2127`）——
抬高亮度、给一层极淡的蓝灰，既保留暗色沉浸感，又让代码与背景之间留出可辨的层次。

### 为什么加了「标识符来源」这一类检查

上线后发现真实故障：**每个文件都显示「只读」+「无法读取这个文件。」**。

根因是 `fsrepo.js` 用到了 `MAX_EDIT_BYTES` 却**忘了从 `constants.js` 导入**。
`readFileText()` 里 `if (file.size > MAX_EDIT_BYTES)` 抛 `ReferenceError`，
又被自身的 `try/catch` 吞成 `reason: "error"`，界面只显示兜底文案 —— 每个文件都如此，
用户完全无从判断。（这个缺陷已修复。）

`node --check` 只看语法，过；原来的一致性检查只查「导入的东西有没有被导出」，也过。
于是补了两道防线：

1. **静态**：`verify.mjs` 新增第 4 类检查 —— 模块里被使用的裸标识符，若既没 `import`
   也没声明，直接判错。已用「故意删掉那行导入」做过反向验证：精准报出
   `fsrepo.js: 使用了标识符 "MAX_EDIT_BYTES"…`，退出码 1。
2. **动态**：`smoke.mjs` 新增第 [9] 段，用假句柄真正调用 `readFileText()`，覆盖
   正常/BOM/超限/二进制/非 UTF-8/不存在/无权限/越权路径 八种情形，
   并有一条反回归断言：**成功路径绝不能返回 `reason:'error'`**。
3. **版本登记同步**：`manifest.json` 与壳内 `FALLBACK_MANIFEST` 是同一份内容存了两遍，
   只改一处不会报错、只会在首屏兜底时悄悄指向旧版本 —— 现在会被逐字段比对拦下。

教训：**判据函数测了，不等于用它拼起来的 IO 主路径测了。**
`smoke.mjs` 原来只测 `safeName` / `langKeyFor` 这类纯函数，从没碰过 `readFileText`，
所以才让一个 `ReferenceError` 潜伏到用户手上。

此外，错误在界面上的呈现也一并改了：读失败时不再只给一句兜底文案，
而是把**异常类型、异常消息、文件路径、当前权限、根目录**原样列出（等宽、可复制），
`NotAllowedError` 也单独归为「无读权限」而不是混进「未知错误」。

> 接线冒烟测试里有一类断言值得说明：它**不匹配中文文案**，只断言「存在一个持久可见的告警容器，
> 且里面带上了真实异常名」——文案改字不会让测试假阴，而真正该守住的契约（错误必须持久可见、
> 异常原因必须透出）始终被覆盖。

### 为什么加了「跨文件冗余数据同步」这一类检查

**同一份数据存了两遍的地方，只会「悄悄不一致」，不会报错。** 本工具里有三处：

| 冗余数据 | 存在哪两处 | 不同步的后果 |
|---|---|---|
| 版本登记 | `manifest.json` ↔ 壳内 `FALLBACK_MANIFEST` | 断网 / 首屏兜底时悄悄指向旧版本（v1.0.1 加） |
| 品牌图形 | `V1/index.html` 的页面 logo ↔ 壳的页签 favicon | 页签和页面里是两个不同的图标，用户一眼看出来（v1.0.2 加） |
| Web 字体族名 | 壳 `<link>` 的 `family=` ↔ `V1/style.css` 的 `--font-sans` / `--font-mono` | 字体静默不生效，页面照常渲染、零报错（v1.0.2 加） |

三处都是**用户看得见、却没有任何机制会报错**的形态，所以固化成静态检查。
顺带记两个提取上的坑（第一版就是这么误报的）：

1. 内联 SVG 的 `href` 值**内部含单引号**（为了不与 HTML 属性的双引号冲突），
   所以不能写成 `href=["']([^"']+)["']` —— 那样会在值里的第一个单引号处提前截断，
   提取出来的只有半截 URI。
2. 直接全文扫 `<link` 会把**壳脚本里的正则字面量**（`/<link[^>]*>/`）当成真标签抓出来。
   现在只扫 `<head>` 区域。

两个检查都做过**反向实验**：故意改坏一处 → 立刻报红并退出码 1；恢复 → 重新全绿。
报错信息会把两边的数据并排打出来，不用再去翻文件找差异。

## 已知限制

1. **必须 HTTP 访问**，`file://` 双击不可用（平台限制，非实现缺陷）。
2. **拖拽文件夹只能读、不能写**，故未启用——引导用户走「选择文件夹」。
3. 目录扫描上限 2 万条；超出会提示「未列全」，需要缩小根目录范围。
4. 单文件可编辑上限 3 MB。
5. 非 UTF-8（GBK / UTF-16 等）文本文件不开放编辑，只读提示。若后续要支持，需要在保存时保留原编码——
   属于独立课题，不宜顺手做。
6. 移动 / 重命名大文件或大目录时需要整份复制，是 API 限制导致的开销。
7. 外部程序同时改动同一文件时**没有冲突检测**：本工具以内存中的编辑器内容为准覆盖写。
   多人/多程序并发编辑同一项目的场景需要额外机制，一期未做。
8. **不能嵌在 iframe 里使用**——这是 Chrome 的硬性限制（跨域子框架禁止调用文件系统访问 API），
   不是本工具的缺陷。表现为点击「选择文件夹」无反应；页面会主动告警并提供跳转独立标签页的入口。
   （同理，`chrome-extension://`、各种「网页内嵌预览」面板都受此限制。）
9. **字体走外链**（Google Fonts），是本工具唯一的外部依赖。断网时仅字形降级为系统字体，
   功能不受影响；若要彻底离线，把字体文件放进 `vendor/` 并改壳的 `<link>` 为本地路径即可。
10. Markdown 渲染器**不支持内联 HTML**（有意取舍，见「Markdown 编辑 / 预览双模式」），
   写 `<div>` / `<span>` 会原样显示为文字。

## 单文件分发（`dist/`）

`dist/code-workspace-v1.html` 是**自动生成**的分发形态：把壳、样式、全部 ESM 模块、离线编辑器包
拼成一个 HTML，**双击 `file://` 即可打开**，适合外发或离线演示。

```bash
# 在 web-toolbox 仓库根目录
node tools/_build/build-snapshot.mjs code-workspace     # 输出 dist/code-workspace-v1.html
```

> ⚠️ **快照里仍然不能用文件系统 API**——`file://` 下浏览器会直接拒绝授权，这是平台限制。
> 因此快照的价值在于「离线也能起界面」，**完整功能仍需 HTTP 访问**。
> 产物头部有 banner 标注来源与重新生成命令，**请勿手改**——改 `V1/src/` 后重新构建即可。
